# AI Product Description & Title Generator — Spec Kit Plan

> SaaS plugin that generates AI-powered product titles and descriptions for Gulf e-commerce businesses.
> **Stack:** Next.js 14 · Django 5 + DRF · PostgreSQL · Claude AI (provider-agnostic)
> **Methodology:** Spec-Driven Development (SDD) with GitHub Spec Kit + Claude Code

---

## Constitution (Non-Negotiables)

Set this once in `/constitution` before any phase begins. The AI agent will enforce these rules across every spec.

```
1. Multi-tenant: every database query is scoped to the org — no data leaks between tenants.
2. Provider-agnostic AI client: swap Claude / OpenAI / Gemini via ENV variable, zero code changes.
3. Arabic-first outputs: all AI generations support Gulf dialect Arabic + English.
4. All features ship behind feature flags — no broken production experiences.
5. Every endpoint has OpenAPI docs via drf-spectacular at /api/docs/.
6. Cost controls enforced per org — Claude API spend capped at plan limits, hard stop enforced.
```

## Phase 2 — Core AI Generation Engine

**Timeline:** Weeks 2–3  
**Goal:** Build the AI engine standalone before any UI. This is the core value of the plugin.

### Spec Kit workflow

```
/specify  →  /plan  →  /tasks  →  /implement
```

### `/specify` prompt

```
/specify Build the AI generation engine for the product description plugin.

Input (POST /api/generate/product-content/):
- product_name: string (required)
- category: enum [fashion, food, electronics, beauty, home, other]
- price: decimal (optional, used for tone calibration)
- target_audience: string (optional)
- tone: enum [professional, casual, luxury]
- language: enum [ar, en, bilingual]

Output (JSON):
{
  "title": string,
  "short_description": string (≤ 160 chars),
  "long_description": string (≤ 500 chars),
  "keywords": string[],
  "seo_meta": string (≤ 155 chars)
}

Additional requirements:
- AIClient class with adapter pattern (Claude default, OpenAI/Gemini switchable via AI_PROVIDER env)
- Separate prompt templates for Arabic Gulf dialect and English
- Enforce JSON schema on AI response (retry once on malformed output)
- Track token usage per org: tokens_in, tokens_out, cost_usd, model, created_at
- Redis cache: key = hash(org_id + inputs), TTL = 24 hours
- Per-org monthly token budget middleware: 429 response when limit exceeded
- Streaming SSE endpoint: GET /api/generate/stream/?session_id=X
```

### Tasks (from `/tasks`)

- [ ] `AIClient` base class with `generate(prompt, system, max_tokens)` interface
- [ ] `ClaudeAdapter`, `OpenAIAdapter`, `GeminiAdapter` — selected by `AI_PROVIDER` env
- [ ] Arabic Gulf dialect system prompt template (professional / casual / luxury variants)
- [ ] English system prompt template (professional / casual / luxury variants)
- [ ] `GenerateProductContentView` (DRF APIView) — validates input, calls AIClient, returns structured JSON
- [ ] `AIUsage` Django model: `org, model, tokens_in, tokens_out, cost_usd, created_at`
- [ ] `TokenBudgetMiddleware` — checks org monthly usage before every generation request
- [ ] Redis cache layer (django-redis): cache key = `SHA256(org_id + sorted inputs)`
- [ ] SSE streaming endpoint — yields partial AI tokens as `text/event-stream`
- [ ] Unit tests: AIClient mock, prompt template rendering, token budget enforcement

### Prompt template structure

```
System prompt (Arabic Gulf dialect):
"أنت خبير تسويق متخصص في التجارة الإلكترونية الخليجية.
مهمتك كتابة عناوين وأوصاف منتجات جذابة لجمهور خليجي.
اللهجة: {tone_ar}. الأسلوب: مباشر، واضح، مقنع.
الرد يجب أن يكون JSON فقط بالشكل المحدد."

"اكتب عنوان ووصفاً للمنتج التالي:

الفئة: {category}
السعر: {price}
الجمهور المستهدف: {target_audience}"
```

## Phase 5 — Unified Social Inbox

**Timeline:** Weeks 7–10  
**Goal:** Connect Instagram DMs, WhatsApp Business, and Facebook Messenger into one prioritised inbox. Every incoming message is AI-tagged for intent and gets an Arabic/English reply draft in real time.

### Spec Kit workflow

```
/specify  →  /plan  →  /tasks  →  /implement  →  /review
```

### `/specify` prompt

```
/specify Build the unified social inbox — connecting Instagram, WhatsApp Business, and Facebook Messenger.

Channel integrations (Meta Graph API + WhatsApp Business API):
- Instagram: receive DMs and post comments via webhook; send replies via Graph API
- WhatsApp Business: receive and send messages via WhatsApp Business API (Meta Cloud API)
- Facebook: receive Messenger messages and page post comments via webhook

Data models:
- SocialChannel: org, platform (INSTAGRAM/WHATSAPP/FACEBOOK), access_token (Fernet encrypted),
  token_expires_at, page_id / phone_number_id, is_active
- Contact: org, name, platform, platform_id (their ID on the platform), ai_score (0-100),
  total_spend, tags, created_at
- Message: org, contact, channel, direction (INBOUND/OUTBOUND), content, content_ar,
  platform_msg_id (unique — prevents duplicate ingestion), intent, ai_draft, ai_draft_ar,
  read, sent_at

AI processing pipeline (Celery task per message):
- Classify intent: READY_TO_BUY / PRICE_INQUIRY / INFO_REQUEST / COMPLAINT / BROWSING
- Score lead delta: -20 to +30 (updates Contact.ai_score)
- Draft reply in Arabic (Gulf dialect) and English
- Only top 20 messages per batch reach the AI (pre-rank by recency + message length)

Inbox frontend (Next.js):
- Unified inbox: all channels in one list, sorted by priority (ai_score + unread + recency)
- Intent badge per message (color-coded: green/yellow/blue/red/grey)
- One-click reply: AI draft pre-filled, edit and send in one click
- Conversation thread view (full history across all channels for a contact)
- Read/unread state management
- SSE streaming: new messages appear without page refresh
- RTL layout for Arabic messages

Webhook ingestion endpoint:
- POST /api/webhooks/meta/ — handles Instagram, Facebook, WhatsApp events (signature verified)
- GET /api/webhooks/meta/ — webhook verification challenge (Meta requirement)

OAuth2 connect flow for channels:
- GET /api/channels/connect/instagram/ → redirects to Meta OAuth
- GET /api/channels/callback/meta/ → exchanges code, stores token encrypted, creates SocialChannel
- POST /api/channels/disconnect/ — removes channel, revokes token

Rate limit: 60 inbox API requests/minute per org (django-ratelimit)
```

### Tasks (from `/tasks`)

- [ ] `SocialChannel` Django model + migration (org, platform, encrypted token, page_id, is_active)
- [ ] `Contact` Django model + migration (org, platform, platform_id, ai_score, total_spend, tags)
- [ ] `Message` Django model + migration (unique platform_msg_id, intent, ai_draft_ar, ai_draft)
